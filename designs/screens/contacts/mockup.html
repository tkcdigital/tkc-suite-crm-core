Design notes

Use the mockup controls: List, Record, Edit. Edit shows the whole record in edit state; the layout is the same as the detail view.

Mapping decisions

  • The 23 OSC summary controls become four panels: Identity, Contact details, TKC programs and groups, Consent. The two-column OSC grid becomes the standard field grid.
  • "Verkoper" is the owner: label Assigned to. It needs an OSC staff to SuiteCRM user map (question 6).
  • Email: primary goes to email1, the two OSC alternatives to extra address rows. OSC has no opt-out per address, only Invalid. Phones: SuiteCRM has one field per type (work, mobile, fax, assistant, home), so a second number of the same type has no place (question 3).
  • Dropped and not shown: Login (Aanmelding), Reset password, SLA list, ERT, Test, Surveys, Outreach activity, the browser tab "Nieuw tabblad 1", Accept and Reject buttons (Case queue work).
  • Subpanels: Cases and Opportunities as asked. Tasks, Notes and Attachments sit in one collapsed Activities and history subpanel. The audit log is the standard Audit tab.
  • List view: SPAM contacts (365 in the test system) are hidden by a default filter chip, not deleted. The owner decides about import (question 14).
  • Marketing opt-in is the inverse of email_opt_out. The mockup shows it in the OSC sense (Yes = opted in). Lawful basis is shown only if legal confirms (question 8).
  • Function level shows the raw letters C, M, O until the owner gives labels (question 13).

[custom] items for the architect

  • Yes / No / Not set flags. The OSC flags are nullable. A SuiteCRM bool has no empty state. Options: enum Yes/No with an empty value rendered as a segmented radio, or import empty as No (question 15). Needs an Angular field display and edit component. The Clear button is part of this.
  • Segmented Yes/No control as the edit component for bool fields (approved in the style guide).
  • Email and phone rows with a type. The core email field has primary, opt-out and invalid, but no address type. The phone type list is a view over five fixed fields.
  • Contact type pill in the list and header (enum display component, SPAM in the danger style).
  • CRM modules as chips in view mode (multienum display) and checkboxes in edit.
  • Save and close button.
  • Grouped panel "TKC programs and groups" is standard metadata (a panel with a field grid). Only the field rendering is custom.

Open questions

  • What is "Staat" (CRM modules): contact module access, or something else (question 2)?
  • Keep Freshworks Usergroup (4 contacts, never Yes)? Drop ERT and Test (question 4)?
  • Three-state flags or import empty as No (question 15)? Labels for function level C, M, O (question 13)?
  • Survey opt-in and Newsletter: how do they relate to Marketing opt-in (question 8)?
  • Are other emails, phone types and channel IDs (chat, social) in scope (question 3)?
  • Are Tasks, Notes and Attachments imported, and as Documents or Notes (question 10)?
