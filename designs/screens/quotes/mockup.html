Design notes

Scope and mapping

  • No OSC counterpart: cosmetic only. Structure stays as in SuiteCRM: list columns, Overview panel, Line items panel with groups, totals block, subpanels (Invoices, Contracts, Documents).
  • List is Angular (standard metadata, same table component as Opportunities). Detail and edit are the legacy AOS view inside the shell iframe: the Dawn theme (public/legacy/custom/themes/suite8/css/Dawn/style.css) must carry the same tokens. The mockup shows the target look; the legacy markup is tables, so some spacing needs CSS overrides, not new markup.
  • The line-item editor (edit view) is legacy JavaScript. We restyle inputs, buttons and the table only. No behaviour change. "Add line", group name and remove buttons keep their legacy places.
  • Stage pill colours reuse the status pill family: Draft neutral, Negotiation warning, Delivered info, On Hold outline, Confirmed accent, Closed Accepted success, Closed Lost danger.
  • Currency and number format: euro, Dutch separators (€ 12.450,00). User profile locale must be set to nl-NL; this is a setting, not design.

[custom] items for the architect

  • [custom] Stage as a coloured pill in the Angular list: same enum display component as the Opportunities stage pill.
  • [custom] Link from the list "Opportunity" column to the opportunity record (standard relate field; needs only the column in list metadata).
  • No other custom work. Dawn restyle of the legacy view is CSS only.

Open questions

  • Opportunity has its own quote number OFTYY-NNNN (tkc_reference_c); the SuiteCRM quote has a numeric number (1042). Which number does the customer see on the PDF? Should "Create quote" copy the OFT number into the quote title or a new field?
  • Is the OSC opportunity quote really an AOS quote with line items, or only a number? The OSC export shows no line items (mapping: "no quotes grid").
  • Do we keep the "Billing and shipping" panel and the Contracts subpanel, or hide them in layout metadata to reduce noise?

All data is synthetic.
