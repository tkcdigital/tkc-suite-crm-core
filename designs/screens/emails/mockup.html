Design notes

Emails, SUITE-23. Cosmetic only. OSC keeps emails inside the incident thread, so there is no OSC mapping and no new field. Built on style guide v0.1, light mode only for sprint 1. Synthetic data only.

Decisions

  • Legacy structure kept: module title with Compose and Check mail, folder tree on the left, list, preview, and the compose form. Only the look changes.
  • Same look as Cases and the other redesigned screens: teal primary button, compact table (32 px rows), pills, 2 px focus ring, Roboto. Unread rows are bold with a teal edge, so unread is not shown by colour alone.
  • Related to shows the case reference in mono, with a link. It uses the standard parent (Related to) field of the email.
  • Reply, Reply all, Forward and Create or link are standard legacy actions. The actions sit in the preview header, close to the text.
  • Layout at 390 px: folders turn into a horizontal strip, the list scrolls inside its own box, the preview stacks below. The legacy screen is not responsive by default. The mobile view is a goal for the Dawn override, not a promise.

Legacy build notes

  • Renders in the legacy iframe. The Angular shell CSS does not reach it, so the tokens are compiled into public/legacy/custom/themes/suite8/css/Dawn/style.css (same file as the other legacy screens).
  • Legacy selectors to restyle (the frontend engineer confirms each in the running app): list table (table.list.view), module title, toolbar buttons, folder tree, compose form fields, the editor toolbar.
  • The list columns, folder names and the preview pane in this mockup follow the legacy email client. If a part differs in 8.10, the frontend engineer keeps the legacy part and only restyles it.

[custom] items

None. Everything on this screen is standard legacy. No Angular work. The [legacy] tags mark restyle targets.

Open questions

  1. Which legacy email view does the owner use in practice: this client (folders and preview), or only the list on a Case record? Without that, the restyle covers the client only.
  2. Does the team want emails shown on the Case thread (Cases mockup) instead of this screen? That would be a Cases change, not an Emails change.
  3. Rich text editor: the mockup shows the standard toolbar. A change of editor is out of scope.
