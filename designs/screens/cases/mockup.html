Design notes

Cases (OSC Incident), SUITE-20. Built on style guide v0.1. Source: docs/osc-mapping/incident.md. SLA is dropped (owner decision), so no response or solve clocks appear anywhere. Light mode only for sprint 1. Synthetic data only.

Mapping decisions

  • One layout for detail and edit. Same panels and grid. The Categorisation panel shows its edit state (button Edit). The header Edit button opens the same state. Full-record edit puts every panel in edit.
  • OSC left panel becomes tabs plus panels. Algemeen = General, Categorisatie = Categorisation, Doorzetten = Routing, Berichten = Messages, Details = Details, Geschiedenis = History. Bijlagen, Taken, Koppelingen, Supportcontract become subpanels below the tabs.
  • Status. Header pill shows the full status (12 values). The status bar keeps the four OSC one-click buttons: Wachtend = Waiting, Bijgewerkt = Updated, Onopgelost = Unresolved, Opgelost = Solved. OSC shows them by current status; here they always show.
  • Priority P1-P4 on priority (P4 added). TKC priority is an impact scale and has its own field. Customer priority is a text field until Q7 is decided.
  • Queue and assigned group sit together in Routing, as in OSC. Queue is also a list filter.
  • Thread. Four entry kinds: staff reply, internal note, customer, customer logged by agent. Colour is never the only cue: label, icon, border style and the words “Not visible to the customer”. The composer turns amber and dashed for a note and hides Send. Customer entry defaults the channel to Phone (OSC default).
  • Product list: Oracle Service Cloud, eGain. Category list: Service Request, Complaint, Question, Change Request. Disposition is not on the screen (open Q5).
  • OSC function buttons: see the table below. Self-service banner, smart assistant, decision trees, co-browse, OSN, Hulp and CX Support link are not designed (drop or out of scope).

[custom] items for the architect

  1. Status bar: action group with display logic and one-click handlers (4 buttons). Medium.
  2. Solve as CX, Solve as eGain, Route to Finance: process handlers that set 3 to 8 fields. Medium.
  3. Mark as spam / Not spam: handler that also writes to Contacts, visibility by contact type. Medium.
  4. Thread: entry type, channel, composer entry switch, standard-text buttons, CC/BCC, "logged by agent" kind. Large. Needs a wider description column (see incident.md 2.1).
  5. Status and priority pills: field display component for enums. Small.
  6. Primary contact (required, 1:N relate) and queue / assigned group fields. Small to medium (backend).
  7. Linked opportunities subpanel (new M:N relationship) and Contract subpanel via account. Medium.
  8. TFS project link field. Small.
  9. Standard (restyle only): header actions, tabs, panels, subpanels, bulk mass update, saved filters, filter panel, audit log, sidebar latest-message widget.

Open questions

  1. Q3: primary contact as a new 1:N field? Shown as required.
  2. Q4: does the owner accept 12 status keys and 4 priority keys? Status bar shows 4 of 12.
  3. Q5: keep Disposition? Not shown. Complaint has no OSC source.
  4. Q6: how do group and queue relate? Both are shown. Q7: is customer priority picked or derived? Shown as text.
  5. Q10: collect-before-share, not designed (customer-specific).
  6. Q14: does AOP email the contact on a staff reply? The button label “Send reply” assumes yes, with “Save without sending” as the default (OSC “send on save: never”).
  7. Q16: bodies of the four standard texts. Q20: short channel list (Email, Phone, Web, Chat, Fax, Social, Other) is assumed.
  8. Should the "Assign to me" presets (product and category by case type) stay? The two unlabelled OSC buttons did this.
